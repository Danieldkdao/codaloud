## Sync: where the time currently goes

The app already has three-way content-hash reconciliation, binary download batches, exclusion rules, conflict checks, and partial-success baseline persistence. Its current limits are 100,000 paths, 64 files and 8 MiB per download batch, four per-file upload/delete workers, 32 MiB ordinary files, and 128 MiB explicitly selected files. These are app choices, not provider guarantees. [Sync constants](/Users/danieldao/Desktop/codaloud/src/features/terminal/constants.ts), [planner](/Users/danieldao/Desktop/codaloud/src/features/terminal/lib/sync-plan.ts), [client orchestration](/Users/danieldao/Desktop/codaloud/src/features/terminal/actions/sync-workspace.ts).

The remote manifest recursively visits and SHA-256 hashes every eligible file on every refresh. Local hashes have an in-memory size/mtime cache, which disappears on app restart. Upload and delete verification launch a separate sandbox command for each file; uploads also check/create parent directories through individual SDK calls. Downloads inspect metadata through a command before each batch, then transfer batches sequentially. The local hash helper yields between chunks but first reads the entire file into a `Uint8Array`. These are the main optimization seams. [Sandbox service](/Users/danieldao/Desktop/codaloud/src/features/terminal/server/sandbox.ts), [terminal request handler](/Users/danieldao/Desktop/codaloud/src/features/terminal/server/terminal-api.ts), [client orchestration](/Users/danieldao/Desktop/codaloud/src/features/terminal/actions/sync-workspace.ts).

The existing text `Sandbox file changed during sync` is emitted by content/version and size comparisons, including before PUT/delete or when downloaded bytes differ from the previously captured manifest. It is not itself evidence that Daytona stopped or the request timed out. Preserve this conflict protection and improve diagnostics with path, phase, expected version, and retryability. Do not silently overwrite the user’s intervening changes. [Terminal request handler](/Users/danieldao/Desktop/codaloud/src/features/terminal/server/terminal-api.ts), [download service](/Users/danieldao/Desktop/codaloud/src/features/terminal/server/sandbox.ts).

## SDK facts that constrain sync

Daytona `downloadFiles([{source}, ...], timeoutSec)` supports per-file failures; request-level failures reject. Buffer downloads retain the complete result in memory. The destination-file overload streams, and `downloadFileStream` is limited to Node/Bun-compatible runtimes. Explicit timeout values are seconds. [Daytona FileSystem reference](https://www.daytona.io/docs/en/typescript-sdk/file-system/).

Installed `0.210.0` sends a single multipart download request containing all paths. It parses the response as a stream in Node and as a buffered response in browser/serverless runtimes. Without destinations, it still accumulates each returned file buffer. Raising batch file count reduces request overhead; it does not mean the SDK starts a separate network request per file. [Installed implementation](/Users/danieldao/Desktop/codaloud/node_modules/@daytona/sdk/esm/FileSystem.js:273).

Expo 57 file metadata modification times are milliseconds. `File.open(FileMode.ReadOnly)` and `FileHandle.readBytes(length)` support bounded repeated reads. Directory watchers exist, but iOS child notifications are coarse; watchers stop when their target is deleted or renamed. A watcher or directory mtime alone cannot establish that a recursive subtree’s content is unchanged. [Expo 57 FileSystem](https://docs.expo.dev/versions/v57.0.0/sdk/filesystem/), [installed watcher types](/Users/danieldao/Desktop/codaloud/node_modules/expo-file-system/src/FileSystemWatcher.types.ts).

The installed Expo downloader streams directly to its target on Android and can leave a partial file after a mid-transfer error. On iOS it downloads to a temporary location before moving into place. Download to a unique staging path and verify before replacing a canonical local file on either platform. [Installed File source](/Users/danieldao/Desktop/codaloud/node_modules/expo-file-system/src/File.ts:45).

Node 22 offers `mtimeNs` and `ctimeNs` with `stat(..., {bigint:true})`, plus inode/device identifiers. Precision remains filesystem-dependent. [Node 22 file system reference](https://nodejs.org/docs/latest-v22.x/api/fs.html#class-fsstats).

Daytona rate limits are organization-wide and operation/tier-dependent. Handle 429s using exposed retry headers and bounded exponential backoff; measure request counts instead of treating concurrency as an unlimited performance knob. [Daytona limits](https://www.daytona.io/docs/en/limits/).

## Recommended sync design

These are engineering recommendations inferred from the SDK capabilities and current code:

1. Persist the local metadata/hash cache per project and cache-schema version. Include path-policy version and invalidate entries after saves, renames, deletes, imports, branch changes, or native Git worktree mutations. Missing/invalid metadata or cache data forces rehashing. Never assume a same-size file is unchanged solely because milliseconds collide.
2. Persist remote hash entries outside the synchronized workspace. Reuse hashes only after matching regular-file metadata, preferably size, nanosecond mtime/ctime, inode and device. Re-stat around each new hash and reject a racing file. Detect disappeared paths on each metadata walk. Use atomic cache replacement and tolerate absent/corrupt cache state.
3. Continue cheap enumeration/stat checks when arbitrary PTY commands can mutate the tree. Skipping all folders based on directory mtime would miss edits to existing child files. A fully trusted dirty-path journal is a separate feature with invalidation, overflow, restart, and external-writer recovery requirements.
4. Hash cold files in bounded chunks, closing handles in `finally`. Native synchronous operations must yield periodically; remote scans can stream hashes rather than allocating a whole 128 MiB file. Bound cache/output entry counts and metadata response size.
5. Run two to four small-file download batches through a worker queue and retain a strict total-byte budget. Increasing from 64 to approximately 128–256 paths is reasonable only with the byte cap intact. Keep oversize files on a separately limited path; do not run four 128 MiB buffered downloads together.
6. Batch remote precondition checks and parent directory creation into a single validated command per upload group. After checks, use SDK `uploadFiles` for bounded groups. Preserve a expected-hash check for every canonical write/delete and update the baseline only for confirmed results.
7. Avoid broad retries of mutating operations. Retry only a failed safe read, or a mutation whose idempotency/precondition proves retry safety. An actual remote edit should yield a conflict, while a timeout should yield a transport failure.
8. Record scan duration, hash hits/misses, bytes hashed/transferred, batch count, API request count, per-phase duration, retries, and peak outstanding bytes. Benchmark unchanged warm sync separately from cold first sync and stopped-sandbox startup. A few seconds is a warm-sync target, not a guaranteed duration for arbitrary repositories or hundreds of megabytes.

For an 8 MiB batch and four simultaneous batches, payload bytes alone total 32 MiB. SDK buffers, the encoded response allocation, native response buffers, and decoded views can coexist. A byte budget therefore matters more than raw file count. Release each batch promptly after applying verified files. This estimate follows the current encoder and SDK buffering behavior, not an observed device memory measurement. [Binary batch encoder](/Users/danieldao/Desktop/codaloud/src/features/terminal/lib/sync-download.ts), [installed SDK](/Users/danieldao/Desktop/codaloud/node_modules/@daytona/sdk/esm/FileSystem.js).

## Terminal Git and `.git` synchronization

The app uses a real local `.git` directory and a native libgit2 engine; normal file APIs deliberately reserve metadata paths. The current terminal sync excludes `.git` on both client and server. [Native Git implementation](/Users/danieldao/Desktop/codaloud/modules/local-workspace/cpp/git-core.cpp), [sync planner](/Users/danieldao/Desktop/codaloud/src/features/terminal/lib/sync-plan.ts), [server path guard](/Users/danieldao/Desktop/codaloud/src/features/terminal/server/sandbox.ts).

Git’s own FAQ warns that continuous file-by-file syncing can leave partial refs and objects, corrupt repositories, or lose data. Its recommended transport is push/fetch. Raw repository mirroring requires the entire repository, including worktrees, to stay quiescent throughout transfer; verify the result with `git fsck`. [Git FAQ: transfers](https://git-scm.com/docs/gitfaq#Documentation/gitfaq.txt-TRANSFERS).

Git bundles transfer committed objects and refs, support full or incremental history, and can be cloned/fetched. They do not reproduce index, working-tree state, configuration, or hooks. A bundle cannot receive a push. [Git bundle documentation](https://git-scm.com/docs/git-bundle).

Metadata may refer to an external common directory or contain absolute worktree paths, so an arbitrary `.git` tree is not automatically portable. [Git repository layout](https://git-scm.com/docs/gitrepository-layout).

Recommendation: support advanced terminal Git with a real repository resident in the sandbox, bootstrapped through Git clone/fetch or a deliberate snapshot/import operation. Synchronize worktree files separately and exchange commits/refs through Git transport. Do not feed `.git` into the normal three-way per-file planner. If identical index/stash state is required, implement a serialized, quiesced, verified metadata snapshot with an explicit ownership model and atomic replacement. Never replace remote metadata while PTY Git, local native Git, or background GC is writing. Native libgit2 currently accepts HTTPS GitHub remotes; local bundle transport is not an existing production app operation. [Native remote implementation](/Users/danieldao/Desktop/codaloud/modules/local-workspace/cpp/git-remotes.cpp).

## Route presentation without the background press-down

Project routes already use `expo-router/js-stack`; their layout documents a previous native modal stall. The JS stack can retain routes, providers, and screen contents while changing presentation alone. [Project layout](/Users/danieldao/Desktop/codaloud/src/app/projects/[projectId]/_layout.tsx).

Installed JS-stack options allow only `card`, `modal`, and `transparentModal`. `transparentModal` keeps the previous screen rendered, prevents it from animating out of place, and selects a vertical slide. Use an opaque themed incoming card, overlay, vertical gesture, and `detachPreviousScreen:false` while retaining existing `detachInactiveScreens:false` and `freezeOnBlur:false`. This is a compatible way to restore the desired slide without reintroducing the native controller dependency. It is an implementation recommendation, and needs simulator tap/gesture verification under terminal load. [Installed stack options](/Users/danieldao/Desktop/codaloud/node_modules/expo-router/build/react-navigation/stack/types.d.ts:274).

Native `Stack` also supports full-screen and form-sheet presentations. Deep-linked nested modals need an anchor route to preserve their background navigation context. Neither feature guarantees tap responsiveness by itself. [Expo modal guide](https://docs.expo.dev/router/advanced/modals/), [Expo 57 Stack](https://docs.expo.dev/versions/v57.0.0/sdk/router/stack/).

Avoid waiting for a sync, terminal mount, file save, or inference before dispatching an ordinary route-open action. Keep route-opening callbacks independent of expensive work, remove stale overlays from hit testing, and verify repeated open/dismiss plus rapid alternate taps while terminal output streams.

## Voice and typed command center

LiveKit supports forwarding model tools to the frontend by RPC. Use this for bounded, validated UI actions; return structured confirmation of the actual state. [LiveKit frontend tools](https://docs.livekit.io/agents/logic/tools/forwarding/).

RPC documentation specifies a 15 KiB UTF-8 legacy payload limit, 64-byte method names, and timeouts spanning the complete request. The installed `livekit-client 2.22.3` source instead defaults to 15,000 ms and supports larger data-stream RPC between capable peers. Set the timeout explicitly and retain the app’s existing 12,000-byte payload cap for compatibility with the Node worker and mixed protocol versions. [RPC reference](https://docs.livekit.io/transport/data/rpc/), [installed RPC client](/Users/danieldao/Desktop/codaloud/node_modules/livekit-client/src/room/rpc/client/RpcClientManager.ts:59), [voice payload guard](/Users/danieldao/Desktop/codaloud/src/features/voice/voice-workspace.ts).

LiveKit Agents supports typed messages over `lk.chat`, `generateReply`, and text-only session configuration. This still uses a room/agent session. [Text and transcriptions](https://docs.livekit.io/agents/multimodality/text/). To meet the requested session-free text path, call the app’s existing authenticated text/inference route directly and share the same tool schemas and UI dispatcher; do not start LiveKit, microphone capture, STT, or TTS just to type. Model inference still has its normal credit cost.

Current voice is scoped to the code route and its contextual inline request. A UI command center that opens Files/Git/Agents must outlive those route changes; move the relevant session ownership above those routes, while terminating safely on project/user change or app background. Keep frozen editor-context validation for editing tools separate from route-state commands. [Voice provider](/Users/danieldao/Desktop/codaloud/src/features/voice/hooks/workspace-voice-provider.tsx), [conversation lifecycle](/Users/danieldao/Desktop/codaloud/src/features/voice/hooks/use-voice-conversation.ts), [inline tools](/Users/danieldao/Desktop/codaloud/src/services/ai/inline-voice-tools.ts).

Recommended action contract: an allowlisted destination or panel, a validated project/file identifier, a request ID, and a structured result. Authenticate RPC caller identity against the linked agent/user, cap results and paginate, reject unknown actions, and deduplicate irreversible actions. A missed RPC acknowledgement must not cause the agent to retry a commit or command blindly. Execute long commands/commits through the existing task/command paths and return their operation IDs; do not hold a short UI RPC open for their entire runtime.

Render conversational replies, search rows, file results, state confirmations, and compact command summaries in one persistent bubble. Store bounded result descriptors rather than raw file bodies or unbounded logs. Keep the plan in its existing panel, as requested. File result rows should carry project identity and a real navigation target, and share the same manual navigation callbacks.

Expo GlassEffect is native Liquid Glass only on iOS 26+ and falls back to a regular view elsewhere. Check API availability before rendering and honor reduced transparency. Reanimated layout transitions provide size/position animation with reduced-motion controls. Use the app’s semantic themed surface on Android and older iOS, and animate the same command-center container between input, listening, results, and reply states. [Expo 57 GlassEffect](https://docs.expo.dev/versions/v57.0.0/sdk/glass-effect/), [Reanimated layout transitions](https://docs.swmansion.com/react-native-reanimated/docs/layout-animations/layout-transitions/).

## Subscriptions and trial cancellation

The app already exposes Customer Center inside Billing’s Subscription tab, but this does not provide a prominent direct cancellation path. [Billing screen](/Users/danieldao/Desktop/codaloud/src/features/billing/components/billing-screen.tsx), [RevenueCat adapter](/Users/danieldao/Desktop/codaloud/src/features/billing/revenuecat-client.ts).

RevenueCat Customer Center requires purchases UI 8.7.0+ and supports `presentCustomerCenter`; the installed 10.10.2 satisfies that version requirement. The RevenueCat account feature itself is available on Pro/Enterprise. Do not make basic cancellation depend on Customer Center being configured or accessible. [React Native integration](https://www.revenuecat.com/docs/tools/customer-center/customer-center-react-native), [Customer Center feature](https://www.revenuecat.com/docs/tools/customer-center).

The installed React Native SDK’s `Purchases.showManageSubscriptions()` is iOS 13+ only. Use it for iOS native management; Android can fetch `getCustomerInfo().managementURL` and open it with React Native Linking. A management URL can be null, so show a recoverable explanation or an appropriate store management fallback. [Installed SDK declaration](/Users/danieldao/Desktop/codaloud/node_modules/react-native-purchases/dist/purchases.d.ts:1001), [RevenueCat management guidance](https://www.revenuecat.com/docs/subscription-guidance/managing-subscriptions), [customer info](https://www.revenuecat.com/docs/customers/customer-info).

Cancellation does not mean immediate entitlement removal. A canceled trial ordinarily remains entitled for the rest of the trial period, and account deletion does not cancel the store subscription. Refresh status after returning to the app and display canceled-renewal/access-end state from CustomerInfo/server billing data. The app should return to Free when the store entitlement expires, rather than setting Free optimistically when the management UI closes. [RevenueCat trial flow](https://www.revenuecat.com/docs/integrations/webhooks/event-flows), [RevenueCat management guidance](https://www.revenuecat.com/docs/subscription-guidance/managing-subscriptions).

## Native scan and conditional manifest verification

The device scan now executes in the existing Expo Modules AsyncFunction worker. It streams SHA-256 through the native workspace implementation and persists hints beside the workspace, keyed by size, inode, device, mode, and nanosecond modification/change timestamps. Warm scans still inspect metadata to detect terminal writes and edits; they read zero unchanged file contents. Cache files are limited to 32 MiB, manifests to 16 MiB, and individual selected files to 128 MiB. Native file limits and scan deadlines prevent unbounded traversal. [Expo Modules AsyncFunction](https://docs.expo.dev/modules/module-api/) documents dispatch away from the JavaScript thread for native async work.

An unchanged remote scan returns a fingerprint confirmation instead of repeating the full manifest. The client fingerprints its persisted common baseline; the sandbox compares the sorted UTF-8 path/hash pairs after checking file metadata. A differing fingerprint returns the full manifest, while a matching one reuses that exact baseline. Transfer preconditions and final verification still protect against subsequent changes. This is an application-level JSON protocol rather than an HTTP 304 response. [HTTP conditional request semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-13) motivate avoiding repeated representations; [Daytona process documentation](https://www.daytona.io/docs/en/typescript-sdk/process/) confirms command stdout is returned through executeCommand, so reducing output also reduces the upstream response.

The isolated native benchmark and simulator scan measurements are saved in [native-sync-benchmark.json](native-sync-benchmark.json). The separate direct SDK download benchmark remains in [sync-benchmark.json](sync-benchmark.json). Neither establishes a guarantee for first-time large downloads over a mobile network.

The baseline fingerprint uses native `digestStringAsync(SHA256)` from [Expo 57 Crypto](https://docs.expo.dev/versions/v57.0.0/sdk/crypto/). The installed Expo Modules default AsyncFunction dispatch queue is shared and serial. Local workspace operations now use a dedicated concurrent queue, while the native per-project mutex still serializes workspace mutations. On the simulator, fingerprint time fell from 1,849 ms to 71 ms; the completed warm sync of 50,174 files took 4,099 ms, with zero content transfers and zero rehashed files on either side.

A simulator terminal closure occurred while the panel remained retained, with close code 1001 and reason “Stream end encountered.” This establishes a transport closure, rather than route unmounting; it does not identify which network hop ended the stream. The gateway now sends protocol pings every 20 seconds and terminates connections that miss the following pong interval, releasing its timer and listeners on close. This follows the [ws heartbeat guidance](https://github.com/websockets/ws#how-to-detect-and-close-broken-connections). A reconnect control remains available after a dropped connection. There is no automatic replay of terminal input or commands.


The native cache now updates its existing entries in place, prunes deleted/excluded paths, moves JSON maps into responses, and leaves an unchanged cache file untouched. The 50,000-file host warm scan peak dropped from 114.61 MiB to 51.53 MiB; cold peak dropped from 86.16 MiB to 62.34 MiB. The client validates hash records without duplicating them, checks path rules only for differing files during planning, and saves its common baseline only when it changes. An oversized persisted baseline is rejected before planning. Temporary Hermes measurements found per-sync allocation churn dropped from 513.85 MiB to 234.57 MiB. That is allocation traffic, not retained heap. The final sampled used JavaScript heap was 101.16 MiB with 124 MiB reserved and 23.57 MiB external.

Debug simulator RSS had substantial transient peaks: one warm-sync sampling session peaked at 790.38 MiB; a later session after the fixes peaked at 692.48 MiB and settled to 203.67 MiB. These runs had different initial memory and host load, so they do not establish a controlled RSS reduction or a real-device memory guarantee. Native host, JavaScript heap and full-process memory measurements answer different questions. The raw measurements and caveats are preserved in the benchmark JSON.

Sandbox preparation now waits for an existing starting, stopping, or resizing transition before configuration/start calls, using the remaining portion of a 90-second preparation budget. This prevents issuing configuration requests while a known transition is underway; other provider failures still surface and do not create replacement sandboxes. The installed SDK supports the corresponding wait methods. [Daytona Sandbox reference](https://www.daytona.io/docs/en/typescript-sdk/sandbox/), [sandbox lifecycle](https://www.daytona.io/docs/en/sandboxes/).

Both Debug and Release iOS simulator builds succeeded. Release runtime memory could not be measured: RevenueCat blocks launch when a test API key is configured in a Release app. No production credentials or purchase protections were changed, and the working development build was restored. A production-key build on a physical device remains necessary for production memory profiling.

A final mobile transfer test created 192 generated 4 KiB files through the native terminal in the 50,174-file workspace. Sync downloaded all 192 with exact on-device byte verification, zero conflicts/failures, 192 server hashes and 50,174 reused hashes. End-to-end sync took 10,306 ms including setup, full changed-manifest delivery, transfers and final verification. This changed-workspace result does not meet a universal few-second target. The generated files were subsequently removed on both sides.
