# RevenueCat setup

The Codaloud RevenueCat project is `projf1fa7c9d`. Its iOS and Android apps use `com.codaloud.development`. For a local Test Store build, set both `EXPO_PUBLIC_REVENUECAT_IOS_API_KEY` and `EXPO_PUBLIC_REVENUECAT_ANDROID_API_KEY` to the Test Store **public SDK key** (prefix `test_`). The ignored local `.env` is currently set this way. Use the platform-specific `appl_` and `goog_` keys only after the matching App Store Connect and Google Play products are configured. Never ship a Test Store key in a release build.

Create a separate RevenueCat **secret API key** and put it in `REVENUECAT_SECRET_API_KEY` on the server. The `test_` public SDK key is not a substitute: account deletion calls RevenueCat's customer deletion endpoint, which requires a secret key. Generate a separate long random value for `REVENUECAT_WEBHOOK_AUTH_TOKEN` and store only the token in the environment, without a `Bearer` prefix. Set the RevenueCat webhook's Authorization header value to `Bearer <REVENUECAT_WEBHOOK_AUTH_TOKEN>`, replacing the placeholder with that token. The endpoint also accepts the token alone for existing configurations. Both server values are required by `src/data/env/server.ts`, so the API will reject an environment where either is blank. Deliver webhooks to the deployed API's `/api/billing/webhook` path; localhost cannot receive RevenueCat webhooks. For this development tunnel, use `https://5jfkq6mx-8081.use.devtunnels.ms/api/billing/webhook`. Copy all four RevenueCat variables to the appropriate deployment environments, keeping the secret and webhook value on the server only.

The catalog has a `paid` entitlement, a current `plans` offering with Pro (internal tier 1) and Premium (internal tier 2) monthly and yearly subscriptions, and a `topups` offering with 100, 200, 500, and 1,000 credit consumables. The app charges for model use, spoken output, connected voice time, agent work and web calls, and paid sandbox use. Credits are debited atomically from monthly balance first, then purchased balance. The product IDs for fixed packs are `codaloud.credits.100`, `.200`, `.500`, and `.1000`. Arbitrary 10–10,000-credit amounts require additional fixed store products or another store-approved purchase design.

The iOS and Android RevenueCat products are registered, but RevenueCat currently reports missing App Store Connect and Google Play credentials, so it cannot verify or configure those store products and prices. Configure the store credentials, create or price the matching products in each store, and run real-store sandbox purchases before release. The Test Store SDK key is for RevenueCat's separate test app and Test Store only; the normal iOS SDK key reads App Store Connect products. Set the intended key in the app environment before testing. A published paywall still needs fetchable products for the selected store.

Test subscription activation, upgrade, downgrade, cancellation, renewal, restore, top-up webhook replay, and store refund behavior on both platforms before a production release. Confirm exact upgrade and downgrade timing against each store's sandbox behavior.
